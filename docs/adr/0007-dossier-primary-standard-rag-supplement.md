# ADR-0007：知识供给双轨——档案为权威框架，标准 RAG 只作纹理补充

- 状态：已接受（2026-09-11）
- 关联：ADR-0002（服务端上下文收口）、ADR-0003（LLM 协议）、`server/src/rag/dossier/`（档案生成/查证/预取）、`server/src/rag/vectorStore.ts`（索引与检索）

## 背景

P1–P27 的实验把 dossier workflow（LLM 预生成结构化剧本档案 + agentic 查证工具）与原有
embedding RAG 做了多轮真实 A/B。结论分两半：

- **档案是事实骨架**：静态场景块把每回合注入从 6.9–7.6k token 压到 0.5–1.3k，事实问答在
  P27 三次跑里 2.80 / 2.80 / 1.20（rag 房 1.00 / 1.60 / 1.60）——档案房首次不输；触发率是
  长期瓶颈（40 个游玩回合只调 1 次查证工具），P26 证伪纯提示词、P27 用服务端预取解决。
- **但描写的"质感"档案给不了**：档案 sceneText 是抽取时的誊抄，覆盖原文 30–60%，细节纹理
  （环境描写、原文措辞、具体数字）大量留在未入档的原文里（gapPct 52–86%）。

同时原有 RAG 管线有多处结构性弱点（本轮侦查实测）：分块在客户端且按 UTF-16 字符计数
（非 token）、PDF 块永无场景归属（scene 过滤空转）、**全仓无 rerank**（纯余弦 topK 直切）、
GraphRAG 索引期烧 LLM 建图、查询期 2 跳扩展无数量上限。

## 决策

1. **双轨分工**：档案 = 权威框架（场景逻辑、线索、NPC、真相/结局），**事实一律以档案/查证为准**；
   RAG = **纹理补充**（环境描写、原文措辞、具体数字），**不承担事实权威**。
2. **检索管线标准化**：递归语义分块（标题→段落→句末，~800 字符/重叠 100）→ 本地 embedding
   （沿用 text2vec 768 维）→ query 检索 **top10** → **本地 cross-encoder rerank** → **top3** 注入。
3. **放弃 GraphRAG**：图与社区摘要在 P20 之后已无消费方（档案取代了"关系情报块"的角色），
   索引期 LLM 成本与查询期无上限扩展都是负资产——删除全部图代码与设置项。
4. **分块搬到服务端**：`POST /api/rag/index` 从"客户端切好块上传"改为"只报 scriptId，服务端
   自读自切"；客户端切块器删除。块只存**字符偏移**，场景归属在查询期用 `coverageGaps`
   的场景锚点现算（解耦索引与档案生成顺序，档案重生成后归属自动跟随）。
5. **注入形态**：档案块之后追加独立小节 `## 原文片段（检索补充·仅作描写素材）`，≤3 块 /
   ≤1.6k 字符；跨场景块最多 1 条并标注「未来场景片段·不得向玩家揭示」；与
   `truths[].revealScene` 锚点窗口相交的块**直接丢弃**（剧透硬闸）。
6. **触发**：每回合固定检索（不做门控——P26/P27 已证 KP 不会主动索取）；query = 场景名 +
   玩家合并发言，规则清洗；**仅当检索最高分低于阈值时**做一次 LLM 改写并重检一次（有界成本）。
7. **reranker 选型**：`onnx-community/bge-reranker-base-ONNX`（q8，279MB），transformers.js
   原生加载；**必须 `logits.sigmoid()` 手工打分**——`pipeline('text-classification')` 内部对
   `[batch,1]` 单 logit 做 softmax 会**恒等返回 1.0，静默失效**。模型在索引时预取；检索时
   缺失则降级为纯余弦 top3（不阻断回合）。
8. **P27 预取保留**：它是事实层的深挖路径（`verify_original`），与纹理层互补；M1 落地后按
   数据复议存废。

## 被否决的替代

- **(a) 继续 GraphRAG + 只升级分块**：图在 P20 后的 A/B 中从未贡献可测收益，却让每次索引多
  一轮 LLM 建图；查询期 2 跳扩展还会把无关块灌进上下文（与 1.6k 预算直接冲突）。
- **(b) 远程 rerank（LLM 打分）**：BYOK 下每回合多一次真实调用（延迟 + 配额），且 zen 网关
  不提供 rerank 端点（公开模型清单 70 个中 rerank/embed 命中 0，`POST /v1/rerank` 404）——
  本地 cross-encoder 零边际成本且离线可用。
- **(c) 切块留在客户端只升级算法**：客户端拿不到档案锚点，无法给块打场景归属——而场景归属是
  剧透硬闸与"场景内优先"的前提。
- **(d) 每回合 LLM 改写 query**：成本不可控；改为"低分才改写"（决策 6）。

## 后果

- 需重建全部存量索引（服务端切块语义与旧索引不兼容）；10 篇量级，成本可接受。
- 首次索引需下载 279MB reranker（索引本身就是重操作，且失败只告警）。
- 两套检索机制并存（档案 + 纹理补充）意味着两处预算，都受 1.6k / 场景块既有上限约束；
  延迟硬约束 = 不得超过 rag 房（P25 教训：注入膨胀会吃掉 TTFT 优势）。
- 验收口径：事实问答沿用 5 问 judge（保连续性）+ 新增**纹理 rubric**（描写是否引用了原文
  可考的细节）+ 延迟对比；2–3 篇剧本 A/B。
- **落地状态（M1，2026-09-11）**：T1 切块器 / T2 本地重排器 / T3 索引编排与 API 断代 /
  T4 场景归属与 query 构造 / T5 检索编排与注入装配 / T6 提示词与开关接线 / T7 图链删除
  均已落地。T7 的删除范围 = 3 个图模块（graphStore/graphRag/graphExtractLLM）+ 4 个图提示词 + 图端点与 `useGraphRAG`/
  `extractionModel` 设置项 + 客户端脚本页图面板与 GraphBrowser 组件；
  `rag.supplement`（默认开）为唯一新增开关。**注意**：本局线索/到访场景的会话级记录
  （ADR-0002 决策 4 的 A3 延后特性，与 GraphRAG 不是一回事）当时**不在删除范围**；
  该延后特性已于 2026-09-12 退役删除（9d8fc10）。
- **rag 房基线代际**：rag 房从 `topK 8 + 图 2 跳扩展` 改为标准管线（top10 召回 →
  rerank top3 + 1.6k 预算），**P10–P27 的 rag 注入量基线不再可比**；T8 验收需重新标注基线。
