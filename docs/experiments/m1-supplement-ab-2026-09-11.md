> 2026-09-11（实验分支 feature/kp-dossier-workflow，T8 / issue #52）。

## 4. 纹理 rubric（新增，ADR-0007 验收口径）

rubric：评"叙事有多具体、多有感官质地"1–5（5 = 明确的感官细节/具体数字/原文措辞；1 = 只有动作与对话转述）。

### 4.1 跨房对比（档案房 vs RAG 房）

| 剧本 | 回合 | rag | dossier | judge note（节选） |
|---|---|---|---|---|
| 火焰交织的盛夏 | 1 | 5 | 5 | 两者描写都具体有质感 |
| 火焰交织的盛夏 | 2 | 5 | 4 | RAG 环境感官细节丰富，DOSSIER 以人物对话为主 |
| 火焰交织的盛夏 | 3 | 5 | 4 | RAG 感官细节如气味/触觉突出，有具体数字；DOSSIER 部分描述稍概括 |
| 古城秘史 | 1 | 5 | 5 | RAG 结构化细节密集；DOSSIER 融入听觉与温度，氛围更沉浸 |
| 古城秘史 | 2 | 5 | 2 | RAG 声光味触觉与节奏；DOSSIER 侧重对话与行为 |
| 古城秘史 | 3 | 5 | 4 | RAG 光/声/材质密集；DOSSIER 视觉突出但维度稍少 |
| **均分** | | **5.00** | **4.00** | |

**这一对比回答不了"补充层有没有用"**，因为 M1-T6 之后**两房用的是同一套检索**：

- RAG 房：检索 top3 原文块 → 直接作为「故事情报」正文注入。**它的整个知识来源就是原文纹理。**
- 档案房：场景档案块（sceneText 是誊抄原文的 30–60%）+ 检索补充小节（同样 top3 原文块）。

即纹理对比实为"原文块"对"档案块 + 原文块"——RAG 房在这一维度天然占优（没有档案块挤占注意力，
全部上下文都是原文）。另外 rag 三次全 5 分 = rubric 顶格无方差。**故补跑隔离实验。**

### 4.2 隔离实验（决定项）：同一篇档案房，补充 ON vs OFF

跑法：同一剧本、同一 play script、同一模型，仅切换 `rag.supplement`
（`AB_SUPPLEMENT=0`，harness 已支持）。

| 指标 | 补充 ON | 补充 OFF | 差 |
|---|---|---|---|
| 事实 judge 均分 | **3.60** | **2.40** | **+1.20** |
| 事实逐题 | 2,5,4,4,3 | 1,4,5,1,1 | |
| 纹理 rubric 均分 | **4.33** | **4.00** | **+0.33** |
| 纹理逐题 | 5,4,4 | 4,3,5 | |
| 整回合 p50 | 56.4s | 54.4s | +2.0s |
| TTFT p50 | 21.9s | 21.5s | +0.4s |
| 补充注入回合 | 9/10 | **0/10** | 开关确实生效 |
| 回合失败 | 0 | 0 | |

→ **补充层在事实维度有正收益**：+1.20（第 1、4、5 题从 1 分抬到 2/4/3——正好是"档案没写全、
需要原文补充"的那类问题）。纹理 +0.33 方向一致但**落在噪声内**（见下方噪声对照）。
代价是 p50 +2.0s、TTFT +0.4s——**远小于 p50 与 RAG 房的差距**（56.4s vs 66.9s），硬约束仍有余量。

### 4.3 噪声对照（关键校准）

**RAG 房在两条臂里配置完全相同**（`rag.supplement` 只门控档案房，见 T6 设计），
所以它两次跑的分差就是**run-to-run 噪声的直接测量**：

| 指标 | RAG 房（ON 臂） | RAG 房（OFF 臂） | 噪声幅度 |
|---|---|---|---|
| 事实 judge 均分 | 1.00 | 1.40 | **0.40** |
| 纹理 rubric 均分 | 5.00 | 4.33 | **0.67** |

对照结论：

- **事实 +1.20 > 噪声 0.40** → 档案房的补充层正收益**站得住**（约 3 倍于噪声）。
- **纹理 +0.33 < 噪声 0.67** → 纹理维度的差异**落在噪声内，不能作为独立证据**。
  纹理 rubric 目前的有效性仅止于"能打出分且不是恒定值"。

> 这条校准也解释了 §4.1 跨房对比为什么不可用：同一配置两次跑就能漂 0.67 分，
> 单次跨房对比（差 1.00）根本分不清是系统差异还是运行噪声。

**因此本轮的纹理验收结论是：rubric 已建立且有非恒定输出，但"补充层提升纹理"未被证实**
（若只看隔离臂的 +0.33 就宣布纹理达标，是在噪声里读信号）。

> 样本量说明：单篇 5 题 / 3 对纹理，LLM judge 与 KP 同模型。要给出纹理维度的强结论，
> 需多篇重复 + rubric 细档化（见 §8 下一步）。

## 6. 调试中发现并修复的 harness 缺陷（重要）

**回合归属错位（会产生假回归）**：`ab-compare.mjs` 的 `waitTurnBatch` 原先只要求
"有任意 appended 消息 + 静默 quietMs"，而回合中途的工具展示消息（骰子/线索/场景切换）
本身就是 appended——它出现后 LLM 还要跑几十秒才出叙述，静默窗口先到就返回，
**本回合的叙事被算进下一回合的批次**。

后果：所有 reply 系统性后移一格，事实问的 judge 拿到的是"上一回合的叙事"，
两房 5 题全判 1 分。**首轮跑就是被这个 bug 判成"档案房从 2.80 退化到 1.00"**——
如果没做交叉核对（拿 P27 的同题回复逐字比对），会误报一次不存在的严重退化。

修复：终结条件改为必须等到**本回合的 kp 叙事或失败系统消息**（`isTerminal`），
开场等待同口径。修复后事实分立刻回到 3.60 / 1.75。

另两处（本次一并修）：补充小节统计字段名取错（`ragContext` → 应从 `wireMessages` 抽）；
档案房注入 token 被近似值覆盖（见 §5）。

### 10.3 纹理与延迟（补测篇）

| 剧本 | 纹理 rag | 纹理 dossier | TTFT p50 rag→dos | 整回合 p50 rag→dos | 补充注入回合 |
|---|---|---|---|---|---|
| 奈落之蛹 | 4.67 | 4.33 | 24.0s → **31.4s** | 50.9s → **46.4s** | 9/10（1525 字符） |
| 无知的幸福（有效档案） | 4.33 | **5.00** | 23.9s → 23.9s | 52.7s → **52.1s** | 10/10（1808 字符） |
| 无知的幸福（生成残缺，见 10.6） | 4.00 | 5.00 | 24.7s → 48.1s | 49.3s → 84.0s | 10/10 |

- **纹理**：补测篇把 rubric 从 T8 的顶格（rag 三次全 5）打散——两篇 rag 分别为
  4.67 / 4.33，档案房 4.33 / 5.00，方向不一致、分差仍在噪声带内（§4.3 噪声 0.67）。
  **维持 T8 结论：rubric 可用，但"补充层提升纹理"仍未证实**。
- **延迟**：T8 的"档案房 TTFT 显著占优"（21.9 vs 33.0s）**未在两篇复现**——
  奈落之蛹档案房 TTFT 反而高 7.4s（它多跑查档案工具），无知的幸福两房打平。
  **修正 §3 的表述**：TTFT 优势是**火焰篇的单篇现象，不是档案房的普遍性质**；
  整回合 p50 两篇档案房都略优（-4.5s / -0.6s，后者近打平）。M1 的延迟硬约束
  （"不超 RAG 房"）**仍然成立**，但不能宣传为"档案房延迟显著更优"。
- **残档篇的反面证据**（10.6）：同一篇在生成残缺（2 场景 / 3% 覆盖）时的档案房
  整回合 p50 84.0s ≫ rag 49.3s、TTFT 48.1s ≫ 24.7s —— 档案太薄时 KP 反复查档案
  （`lexical_search` 6 次 + `scene_list` 6 次 + `verify_original` 1 次），**延迟劣化 70%**。
  这是"档案质量决定延迟"的直接证据，也是 §10.6 该被当回事的原因。

### 10.4 预取（P27）触发：机制确实会触发，但触发率方差极大

T8 报告 §7 记录"20 回合里预取 0 次触发"。补测共四次房间跑（同两篇剧本 × 多次重跑），
逐次实测的预取注入回合数：

| 跑次 | 奈落之蛹 | 无知的幸福 |
|---|---|---|
| 补测首轮（pre-#53，`ab-runtime-m2`） | **4/10**（命中 3，剧透层 4） | **4/10**（命中 3，剧透层 4） |
| #53 修复后（`ab-runtime-m2-post53`） | 3/10（命中 1） | 4/10（命中 3） |
| 全修（`ab-runtime-m2-final`） | **0/10** | 1/10（残档，未命中） |
| 无知的幸福有效档重跑（`ab-runtime-m2-s2`） | — | **0/10** |

命中的样例（取自触发的那两跑）：

- 奈落之蛹 T9：`【剧透层·仅限 KP 内部裁定】…夏盖妖虫侵蚀了祝可，并控制她绑架了李嘉冉…`（命中，带剧透层标注）
- 无知的幸福 T6/T7：人物清单与案件线索的原文摘要（命中）

→ **结论要分层读**：
1. **机制成立**——预取在真实剧本上会触发，命中时正确带出原文结论与剧透层标注；
   T8 的"0 触发"不是机制失效（同一篇剧本重跑即可 4/10）。
2. **触发率不可依赖**——实测在 **0–4/10** 之间剧烈波动，全修后的两次跑又回到 0–1/10。
   它与"场景块内容、覆盖度判定、问句措辞"的耦合使触发高度不稳定。
3. **因此"触发率"不是可用的存废判据**（既不能拿 T8 的 0 次说它没用，也不能拿 4/10 说它可靠）。
   复议应按**分工与命中质量**评估（每回合固定检索供纹理 vs 事实问预取供事实层），
   并接受"它是低频、不稳定路径"这一事实。

### 10.5 补测过程中发现并修复的两个真实缺陷

补语料本身不需要改代码，但**度量出的反常数字**暴露了两个产品缺陷（都已走完
TDD → 审查 → 全量绿 → 关票）：

**#53 档案房场景错配**（commit `01a7e40`）。`fetchDossierContext` 用裸精确匹配找
当前场景，**匹配不上时静默回落到档案第一个场景**——KP 拿到别的场景的权威描述、
在场 NPC、可获线索与覆盖率，并沿三处下游继续指错（检索补充的场景定向、原文查证的
定位窗口、wire 注入列）。实测证据：补测首篇的档案房在"地下工具间"回合拿到的是
`古城科技大学家属院正门`（= `scenes[0]`）的块，而那两个事实题正好被判 fabrication。
修法：归一化匹配改用 `findScene`；**区分两种回落**（房间无场景 → 保留回落首场景，
且场景名与块同源；有场景但匹配不上 → 不注入任何场景块，改为显式「档案未覆盖该场景」
提示 + 不取覆盖率）。

**#54 结束态不落库**（commit `32e74d8`）。`end_game` 只改内存 phase，**从不写
`rooms.phase` 列**——而该列是房间详情 / "继续游戏"入口 / restore 的真源。后果：
已结束的局仍挂在首页入口、重启后复活成进行中。这条直接污染了本轮第一次补测
（某篇在第 10 游玩回合结束，随后 5 个事实追问全部 240s 超时，judge 把"没作答"
判成 1 分并标 fabrication，读起来像"档案房退化 1.00"）。
修法：`setEnding`/`setPhase` 落库 + `flushTurn` 拦截结束态 + `startRoom` 门闩 +
restore 自愈旧数据；harness 侧加**空回复/房间已结束守卫**（`factRound.valid`，
按臂标 invalid 并剔除均分），防止这类度量污染再次伪装成产品退化。

> **流程教训（重要）**：本轮两次"档案房退化"读数（2.80→1.00、1.75）**都不是产品结论**——
> 一次是 harness 回合归属错位（T8 报告 §6），一次是 #54 空回复。**跑出反常数字先怀疑度量，
> 再怀疑产品**；harness 的两道守卫（T8 的 `isTerminal`、本轮的 `factRound`）就是这两次教训的固化。

### 10.6 档案生成稳定性（观察，未立票）

无知的幸福在两次生成中差异极大：**2 场景 / 3% 覆盖**（`有 3 个分节解析失败，
档案只覆盖前 2/5 节`，17 分钟）vs **18 场景 / 56.2% 覆盖**（10 分钟）。前者被
生成器自己的质量警告命中（`sceneText 覆盖率仅 3%…疑似严重欠抽`），但**产物照常落盘
且可开局**——于是 A/B 拿到的是一个残档房的分数（档案房 2.00 vs 重跑 2.20）。

- 生成器**已有**质量警告（`assessDossier` 的 warnings + coveragePct），问题在警告
  **不阻断**：残档会被当作正常档案使用；
- 影响面：单次生成失败不会报错，只是"这一局的档案房表现变差"——静默降质；
- 未立票（本轮只记录）。若要处理，方向是"生成后 coverage 低于阈值 → 重试或提示用户重新生成"。
- **后记（2026-09-12，已立票并修复）**：本节现象按 #55 收口——生成期分节解析失败
  重试加固（抛错也重试；重试后段 maxTokens 16k→32k）；产物期 quality 快照随档案
  落盘 + 开局门闩（startRoom / createSoloRoom）对低覆盖（<30%）/分节失败档案 409
  提示重新生成，不再静默放行。
