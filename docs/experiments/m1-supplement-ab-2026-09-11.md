# M1 验收 A/B：档案房（+检索补充）vs 标准 RAG 房

> 2026-09-11（实验分支 feature/kp-dossier-workflow，T8 / issue #52）。
> 验收 ADR-0007 决策 5/6 的 M1 落地：检索补充层（标准管线：递归切块 → 本地嵌入 → top10
> → 本地 cross-encoder 重排 → top3）注入档案房后，**事实问答不退化、纹理质感可测、延迟不超 RAG 房**。
>
> 相关：`docs/adr/0007-dossier-primary-standard-rag-supplement.md`、`dossier-prefetch-p27-2026-09-10.md`（P27 基线）。

## ⚠️ 语料修正（2026-09-11 追加，先读这条）

**古城秘史不是单篇剧本，是 8 个模组的合集**（正文里《血水》《火焰交织的盛夏》
《穿越时空的旅行者》《重返黑色校园》《奈落之蛹》《早八要迟到了》等按顺序平列，
各占原文一段；142k 字符、15 节）。我们的产品前提是"一个文档 = 一个 story"，
它不满足该前提。

**因此本报告的古城篇数据（§2 的 1.75、§5 的注入统计、§7 的"档案不完整"分析）
不作为验收依据**——把它当单篇剧本处理会导致：场景锚点/场景数远超单篇、上下文切换
在模组之间语义断裂、`fetchDossierContext` 的场景回落会跨模组命中。

**有效验收语料 = 火焰交织的盛夏（单模组，26k 字符）**，另加其隔离臂。经核对，
**这次修正对结论方向没有影响**（§2/§0 的档案房优势本来主要来自火焰篇）；但古城篇
确实暴露了一个**前置语料问题**，已另立为 M2 待办（见 §8）。

> 顺带修正上文一个过软的表述：先前写的"档案完整性是事实分的上限"应改述为
> **"档案在覆盖到的范围内明显更好；在没覆盖到的地方不只是弱，而是会编造"**——
> 古城篇里档案房失分的两题（《奈落之蛹》《火焰交织的盛夏》的细节题，jugde 标了 fabrication）
> 恰好都落在未入档的节段上，而它覆盖到的《血水》那道题是 4:1 赢。

## 0. TL;DR

> 下表**只采用有效语料**（火焰交织的盛夏，单模组）。古城秘史按模组集排除，见开头语料修正。

|---|---|---|

**结论**：**M1 核心目标达成、纹理目标部分达成**。事实层不退化且隔离实验显示**显著正收益**
（+1.20，约 3 倍于实测噪声 0.40）；延迟达标（p50 ≤ RAG 房，补充层自身代价约 +2s）；
补充层按设计稳定注入；GraphRAG 全删、管线全部服务端化。
**纹理 rubric 已交付并产出非恒定分**，但"补充层提升纹理"这一条**尚未证实**（+0.33 < 噪声 0.67）。

**样本量诚实说明**：修正后**有效语料只有 1 篇**（原来指望的第二篇是模组集，被排除）。
"事实不退化"目前是单篇证据 + 隔离实验 + P27 历史三跑的方向一致性；**多篇复现仍待补**
（§8 第 1 项已列为合并后的首要动作）。

  --turns 10 --out training/eval/reports/ab-runtime-m1t8.json

node scripts/eval/ab-runtime-summary.mjs --compare=training/eval/reports/ab-runtime-m1t8.json

- 每篇：索引重建（服务端切块）→ 档案生成 → 两房各 10 游玩回合 + 5 事实问。
- 两篇合计 ~1.5 小时（古城 142k 字符，档案生成单步 41 分钟）。

|---|---|---|---|---|
| 火焰交织的盛夏 | **1.00** | **3.60** | 1,1,1,1,1 | 2,5,4,4,3 |

**与 P27 基线对比**（同一篇「火焰交织的盛夏」，P27 三次跑）：

| 跑次 | dossier 档案房 | rag 房 |
|---|---|---|
| P27b | 2.80 | 1.60 |
| P27f | 2.80 | 1.60 |
| P27a | 1.20 | 1.00 |
| **M1-T8（本次）** | **3.60** | **1.00** |

→ 档案房**不退化**，本次还高于 P27 的两个高分跑次；RAG 房与 P27a 同档。
（判读注意：单篇 5 题、LLM judge 同模型，分差 ±1 属噪声带；这里的方向性一致——档案房在
"剧本里有明确答案"的问题上明显更准。）

**失分构成**（judge note）：RAG 房 5 题全为"答非所问 + 编造"（它把事实追问当成叙事继续写，
甚至编出剧本里没有的孤儿院场景）；档案房失分主要是**答得不全**（如"未点明正文与注释的差异"
"遗漏王金民、法阵等核心解法细节"），属召回不全而非编造。

### 2.2 已排除语料：古城秘史（模组集）

不满足"一个文档 = 一个 story"的前提（理由见开头语料修正）。原始数字与逐题明细仍在

## 4. 纹理 rubric（新增，ADR-0007 验收口径）

rubric：评"叙事有多具体、多有感官质地"1–5（5 = 明确的感官细节/具体数字/原文措辞；1 = 只有动作与对话转述）。

### 4.1 跨房对比（档案房 vs RAG 房）

| 剧本 | 回合 | rag | dossier | judge note（节选） |
|---|---|---|---|---|
| 火焰交织的盛夏 | 1 | 5 | 5 | 两者描写都具体有质感 |
| 火焰交织的盛夏 | 2 | 5 | 4 | RAG 环境感官细节丰富，DOSSIER 以人物对话为主 |
| 火焰交织的盛夏 | 3 | 5 | 4 | RAG 感官细节如气味/触觉突出，有具体数字；DOSSIER 部分描述稍概括 |
| 古城秘史 | 1 | 5 | 5 | RAG 结构化细节密集；DOSSIER 融入听觉与温度，氛围更沉浸 |
| 古城秘史 | 2 | 5 | 2 | RAG 声光味触觉与节奏；DOSSIER 侧重对话与行为 |
| 古城秘史 | 3 | 5 | 4 | RAG 光/声/材质密集；DOSSIER 视觉突出但维度稍少 |
| **均分** | | **5.00** | **4.00** | |

**这一对比回答不了"补充层有没有用"**，因为 M1-T6 之后**两房用的是同一套检索**：

- RAG 房：检索 top3 原文块 → 直接作为「故事情报」正文注入。**它的整个知识来源就是原文纹理。**
- 档案房：场景档案块（sceneText 是誊抄原文的 30–60%）+ 检索补充小节（同样 top3 原文块）。

即纹理对比实为"原文块"对"档案块 + 原文块"——RAG 房在这一维度天然占优（没有档案块挤占注意力，
全部上下文都是原文）。另外 rag 三次全 5 分 = rubric 顶格无方差。**故补跑隔离实验。**

### 4.2 隔离实验（决定项）：同一篇档案房，补充 ON vs OFF

跑法：同一剧本、同一 play script、同一模型，仅切换 `rag.supplement`
（`AB_SUPPLEMENT=0`，harness 已支持）。

| 指标 | 补充 ON | 补充 OFF | 差 |
|---|---|---|---|
| 事实 judge 均分 | **3.60** | **2.40** | **+1.20** |
| 事实逐题 | 2,5,4,4,3 | 1,4,5,1,1 | |
| 纹理 rubric 均分 | **4.33** | **4.00** | **+0.33** |
| 纹理逐题 | 5,4,4 | 4,3,5 | |
| 整回合 p50 | 56.4s | 54.4s | +2.0s |
| TTFT p50 | 21.9s | 21.5s | +0.4s |
| 补充注入回合 | 9/10 | **0/10** | 开关确实生效 |
| 回合失败 | 0 | 0 | |

→ **补充层在事实维度有正收益**：+1.20（第 1、4、5 题从 1 分抬到 2/4/3——正好是"档案没写全、
需要原文补充"的那类问题）。纹理 +0.33 方向一致但**落在噪声内**（见下方噪声对照）。
代价是 p50 +2.0s、TTFT +0.4s——**远小于 p50 与 RAG 房的差距**（56.4s vs 66.9s），硬约束仍有余量。

### 4.3 噪声对照（关键校准）

**RAG 房在两条臂里配置完全相同**（`rag.supplement` 只门控档案房，见 T6 设计），
所以它两次跑的分差就是**run-to-run 噪声的直接测量**：

| 指标 | RAG 房（ON 臂） | RAG 房（OFF 臂） | 噪声幅度 |
|---|---|---|---|
| 事实 judge 均分 | 1.00 | 1.40 | **0.40** |
| 纹理 rubric 均分 | 5.00 | 4.33 | **0.67** |

对照结论：

- **事实 +1.20 > 噪声 0.40** → 档案房的补充层正收益**站得住**（约 3 倍于噪声）。
- **纹理 +0.33 < 噪声 0.67** → 纹理维度的差异**落在噪声内，不能作为独立证据**。
  纹理 rubric 目前的有效性仅止于"能打出分且不是恒定值"。

> 这条校准也解释了 §4.1 跨房对比为什么不可用：同一配置两次跑就能漂 0.67 分，
> 单次跨房对比（差 1.00）根本分不清是系统差异还是运行噪声。

**因此本轮的纹理验收结论是：rubric 已建立且有非恒定输出，但"补充层提升纹理"未被证实**
（若只看隔离臂的 +0.33 就宣布纹理达标，是在噪声里读信号）。

> 样本量说明：单篇 5 题 / 3 对纹理，LLM judge 与 KP 同模型。要给出纹理维度的强结论，
> 需多篇重复 + rubric 细档化（见 §8 下一步）。

## 6. 调试中发现并修复的 harness 缺陷（重要）

**回合归属错位（会产生假回归）**：`ab-compare.mjs` 的 `waitTurnBatch` 原先只要求
"有任意 appended 消息 + 静默 quietMs"，而回合中途的工具展示消息（骰子/线索/场景切换）
本身就是 appended——它出现后 LLM 还要跑几十秒才出叙述，静默窗口先到就返回，
**本回合的叙事被算进下一回合的批次**。

后果：所有 reply 系统性后移一格，事实问的 judge 拿到的是"上一回合的叙事"，
两房 5 题全判 1 分。**首轮跑就是被这个 bug 判成"档案房从 2.80 退化到 1.00"**——
如果没做交叉核对（拿 P27 的同题回复逐字比对），会误报一次不存在的严重退化。

修复：终结条件改为必须等到**本回合的 kp 叙事或失败系统消息**（`isTerminal`），
开场等待同口径。修复后事实分立刻回到 3.60 / 1.75。

另两处（本次一并修）：补充小节统计字段名取错（`ragContext` → 应从 `wireMessages` 抽）；
档案房注入 token 被近似值覆盖（见 §5）。

## 7. 未达标项与已知问题

| 项 | 状态 | 定位 |

## 8. 结论与下一步

**M1 是否达到目标**：**核心目标达成（事实 + 延迟 + 架构），纹理目标部分达成（工具已交付、收益待证）**。

- ✅ 事实层不退化，且隔离实验显示补充层**正收益 +1.20**（约 3 倍于实测噪声 0.40）：
  火焰篇跨房 3.60 vs rag 1.00；对照 P27 基线 2.80/2.80/1.20
- ⚠️ 纹理：rubric 已建立、输出非恒定，但**"补充层提升纹理"未获证实**（+0.33 < 噪声 0.67，§4.3）
- ✅ 延迟硬约束达标（火焰篇 p50 56.4s ≤ rag 66.9s；补充层自身代价 p50 +2.0s / TTFT +0.4s）
- ✅ 补充层按设计稳定注入（9/10 回合，~1.3k 字符，跨场景前缀与 1.6k 预算都对）
- ✅ 架构目标达成：GraphRAG 全删、分块/索引/检索/装配全在服务端、剧透硬闸与场景归属生效
- ✅ 零回合失败（单篇 30 游玩回合 + 10 事实回合）
- ⚠️ **有效语料只有 1 篇**（原定第二篇是模组集，已排除）→ 多篇复现待补

**建议的下一步（按优先级）**：

1. **补语料再跑 1–2 篇单篇剧本**（最高优先）：把"单篇剧本不足"这个前置缺口补上，
   才谈得上"多篇复现"。候选见 §7；跑法同 §9。**这一步不必等合并**——它只是补证据，
   不改代码。
2. **合并决策**：事实与延迟两项验收有正向证据、架构已收敛，**建议合并 main**。
